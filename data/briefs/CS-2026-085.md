## Context

Phase 2 RCAs uncovered two workflow lifecycle defects with a shared missing infrastructure. Cluster C (archival synthesis): Process 3.8 Step 0 Friday archival is dormant — acted-on PM entries never archive, so the `action_taken=true` marker never co-emits `archived_date`, collapsing C3-D1/D2/D3 dimensions. Cluster E (ChangeSet loop stall): CS-2026-056 and CS-2026-057 have been stuck at `approved` for 7+ days with no trigger to advance them to `executed`. Both clusters converge on the same structural absence: a reliable scheduler/worker module.

Confound check (Cluster C × Cluster E) passed — distinct primitives at the RCA level (field-emission-at-write-event vs. state-transition-triggering) — but both depend on the same scheduler infrastructure. Shipping separate schedulers would fragment the ops surface, duplicate P003 circuit-breaker logic, and expand the `Spec-without-runtime-enforcement` anti-pattern footprint. One module, three tenants. See `cgo-logs/rca-runs/2026-04-19-pm-phase2c-changesets.md`.

## Hypothesis

A unified workflow-scheduler module with three tenants at launch — (A) PM write-path hook that co-emits archival lifecycle marker on `action_taken=true` flip, (B) ChangeSet execution queue that pushes `approved` → `executed` via risk-gated auto-advance or manual-push-with-hold, (C) stale-state detection worker that scans any state-machine-backed record and alerts on SLA breach — all wrapped by a shared P003 circuit-breaker primitive, lifts the PM composite by +9–11 pts and unblocks CS-056/057 within 48 hours of E5 shipping.

Ship E5 first as standalone detection-only; it delivers immediate value with zero autonomy delta and zero write-side risk.

## Scope

1. **Scheduler module core** — cron-equivalent + queue primitives, tenant-scoped
2. **Tenant A — PM write-path hook** (C1): on `cross-surface-pm.json` write where `action_taken` flips true, co-emit `archived_date` per Provisional Co-emit-lifecycle-marker pattern. Replaces the dormant Friday Step 0 manual cadence.
3. **Tenant B — ChangeSet execution queue** (E2): on `state=approved`, push to risk-gated execution queue. Risk classifier v1 rules: `autonomy_tier<=1` + surface in {klaviyo, paid_meta, paid_amazon} + L5 pass → auto-advance; else route to manual-push with hold + Slack nudge.
4. **Tenant C — Stale-state detection worker** (E5): daily scan of state-machine-backed records (ChangeSets, PM entries, calendar activities); alert on stall beyond SLA. Generalizable to PM producer-health monitoring (addresses Cluster D edge case E-005). **Ships day 1 standalone.**
5. **Shared circuit-breaker wrapper** — P003 Automated circuit breaker: on per-tenant failure rate >5%, pause tenant + alert. Tenant isolation prevents cross-tenant cascade.
6. **C5 one-time reconciliation worker** — archived_date backfill for acted-on PM entries written before scheduler ships (time-boxed; runs until backlog = 0)
7. **Shadow dry-run for E2** — queue runs read-only for 48h; compares auto-advance decisions to manual ground truth before live cutover

## Measurement Plan

- **Primary:** PM composite eval at post-ship +1 week. Contributes +9–11 pts of the +22–26 pt portfolio projection (C3-D1 +2, C3-D2 +2, C3-D3 +2, C4-D4 +3, C5-D2 +2, C5-D3 +2).
- **E5 ship — immediate:** CS-056 and CS-057 execute within 48h of E5 live. First stall alert surfaces within 24h.
- **Tenant-level:** per-tenant failure rate (circuit-breaker target <5%); E2 auto-advance accuracy vs. shadow dry-run (target ≥95% agreement before live cutover); archival reconciler completion (100% of acted-on PM entries)
- **Window:** 14 days from scheduler core live
- **Falsification criteria:** if CS-056/057 don't advance within 48h of E5 ship, E5 is mis-scoped — escalate to fallback E4 (risk-tier conditional auto-transition only). If composite < 82.3% at post-ship +1 week, activate C4 (scope-narrow to Step 0 archival only).
