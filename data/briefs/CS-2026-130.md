## §10b RESOLUTION PATH ANALYSIS

**Diagnose:** Two command files exist with detailed specs:
- `kenetik-growth-system/commands/cgo-copilot.md` (160 lines, Process 1.5, CGO-facing interface — modes: ask, escalate)
- `kenetik-growth-system/commands/executive-copilot.md` (241 lines, Process 2.10, backend query engine — modes: query, patterns, log)

Both reference each other (cgo-copilot routes to executive-copilot backend). Both are listed in the kenetik-brain skill router. Both reference an "Edge Case Log" as the persistence surface for discovered insights.

**Zero callers exist anywhere.** A grep across the daily pipeline (cgo-daily-pipeline/SKILL.md, README.md, config/*.md) returns no invocations. No state files exist for the Edge Case Log or query log. The result: when Devon has an ad-hoc business question, the answer comes from re-invoking the synthesizer manually each time, which is exactly the redundant work the copilot was specced to eliminate.

The CS-129 round 3 design assumed the copilot was a working surface and named it as the manual-invoke mechanism. That assumption was wrong. CS-129's manual-invoke depends on this CS shipping.

**Remove:** Could remove the spec entirely if not wanted. Devon's directive is to build it, so don't remove. We CAN remove the redundant ad-hoc query work that happens today every time a question is asked — that's exactly what wiring the copilot does (collapses re-invocation overhead).

**Refine:** Both spec files are detailed and don't need rewriting. The gap is wiring + minimal supporting artifacts. The "data marts" the spec references are state files that already exist (`data/shopify-cohorts/`, `data/wholesale/`, `data/paid-media/`, `data/voc/`, `data/subscriptions/`, `data/amazon/`, `data/marketing-calendar/`, `data/performance-memory/`). The copilot can read those today. Refine the cgo-daily-pipeline orchestrator to invoke the copilot as part of the daily run.

**Add:** Three minimal artifacts:
1. **Phase 4.5** in cgo-daily-pipeline (between Synthesis dispatch and close) that runs a standing question set through the copilot and appends answers to Devon's Layer 2 DM.
2. **Standing question list** — a small markdown file Devon can edit to add/remove questions.
3. **Edge Case Log + query log files** — JSONL files for cross-session persistence (analogous to running-log.json's pending_recommendations).

Why this earns its place: the spec's value is "instead of re-running synthesis manually each time you have a question, get answers to standing questions automatically + ad-hoc on demand." Without wiring, Devon pays that re-run cost every query. With wiring, it's amortized into the daily pipeline at known cost.

---

## HYPOTHESIS

If `/cgo-copilot` and `/executive-copilot` are wired into the daily pipeline (Phase 4.5: morning pre-answers from a standing question set) AND remain callable on-demand for ad-hoc queries, the CGO's per-question time-cost drops measurably (target: from ~10-15 min ad-hoc re-synthesis to ~30 sec read-the-answer-in-the-DM for standing questions; on-demand queries get same-quality answers in <5 min via the existing command surface). Insights surfaced via copilot get persisted in the Edge Case Log so the system doesn't forget them.

## PROPOSED CHANGE

### A. Phase 4.5 in cgo-daily-pipeline — "Morning Copilot Pre-Answers"

Wire into `cgo-daily-pipeline/config/task-b-synthesis.md` between Phase 3 (ChangeSet Lifecycle) and Phase 4 (Dispatch). Or as Phase 4 sub-step. The actual integration point depends on whether dispatch-instructions.md is the right host or if it should live in synthesizer scope; recommendation: wire into the dispatch step since the output goes to Devon's Layer 2 DM.

**Pseudocode:**

```
For each standing question in cgo-daily-pipeline/config/cgo-copilot-standing-questions.md:
  Run /executive-copilot query logic against today's data marts +
  today's synthesis output.
  Capture: direct answer + confidence + 1-line follow-up suggestion.

Append to Devon's Layer 2 DM as a "Morning Copilot" section:
  "Q1: <question>
   A1: <one-sentence answer> (confidence: H/M/L)
   ⮕ <follow-up suggestion if applicable>

   Q2: ..."

If any answer reveals an anomaly (z-score >2, or matches anomaly criteria from
executive-copilot.md Step E), auto-log to Edge Case Log (D below).
```
