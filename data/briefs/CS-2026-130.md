## §10b RESOLUTION PATH ANALYSIS

**Diagnose:** Two specced commands sit in `kenetik-growth-system/commands/` (`cgo-copilot.md`, `executive-copilot.md`) with detailed protocols and zero callers. The original CS-130 design proposed building them into the daily pipeline. Devon's directive: don't build, remove. The reasoning: maintenance cost on unused commands is non-zero (they appear in skill routers, plugin packages, role skill files — every reader has to wonder "is this real?"), and there's no business need we can't meet through existing surfaces (the synthesizer + direct queries against existing state files).

The Edge Case Log the copilot specs referenced is a real artifact at `cgo-logs/edge-cases/` (directory of `EC-YYYY-NNN.md` files), managed by the existing `/edge-cases` command. **It stays.** The copilot specs were referencing it as if they owned it; they didn't. Removing the copilot commands doesn't touch the Edge Case Log at all.

The query log the copilot specs referenced never existed. It goes away with the specs.

**Remove:** This IS the Remove step. The copilot commands earn deletion because:
1. Zero callers (verified)
2. Their referenced "data marts" map to existing state files that other commands already query directly
3. The Edge Case Log they cite is owned by `/edge-cases`, not them
4. Maintaining unused command files creates the "spec exists but isn't wired" anti-pattern noise CS-127 already flagged
5. Future natural-language-query needs can be specced fresh against actual requirements rather than this paper design

**Refine:** Strip references to the deleted commands from the four files that reference them (skill router, architecture spec, data-warehouse-status, CS-129's manual-invoke citation).

**Add:** Nothing. Pure subtraction.
