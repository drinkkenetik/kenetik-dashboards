## §10a Hypothesis

Today, two pieces of brand-published copy are scheduled within 7 days carrying `claims_compliance: not_checked`: (1) Matt Hughes IG/FB reels on 5/6 with explicit "TBI recovery and Oxycontin addiction" framing alongside Kenetik brand positioning, including hashtags `#BrainHealth #TBIRecovery`; (2) Mother's Day post 5/10 with the phrase "You deserve clarity and focus on demand." Per Hard Gate 1 of synthesis-instructions.md, neither can ship without Devon claims approval. Per L-011 (HARD GATE for owner validation) and L-035 (HG roster validation), HARD GATE breaches that surface inside the 7-day publish window are a known structural failure mode -- the bulk-content tool currently advances unchecked entries to `scheduled` without the gate firing. **Hypothesis:** Adding a single guardrail line to the bulk-content tool ("any entry with `claims_compliance=not_checked` and a publish date within 7 days blocks scheduling") prevents this category of HARD GATE breach forward-going. Per Resolution Hierarchy Step 3 (Refine), this extends an existing claims-check pattern rather than creating a new approval workflow.

## §10b Resolution Path (Diagnose / Remove / Refine / Add)

- **Diagnose:** Two HARD GATE breaches scheduled within 6 days surface the failure mode. Root cause: bulk-content tool's scheduling logic does not validate `claims_compliance` against the publish-date proximity. The claims-check itself exists and runs (Devon's approval workflow is functional); the gate-tool integration is missing.
- **Remove:** Nothing to remove -- the gate logic doesn't exist yet to be removed.
- **Refine:** Add one validation rule to the bulk-content tool's pre-scheduling pipeline. Extend an existing pattern (the claims-check enum) rather than creating a parallel workflow.
- **Add:** Not warranted as Step 4. Resolution Hierarchy Step 3 (Refine) is sufficient.

## §10e Scope

1. **Bulk-content tool gate:** Add a single validation rule to the pre-scheduling pipeline. Pseudo-code:
   ```
   if entry.claims_compliance == "not_checked" and 
      (entry.publish_date - today).days <= 7:
       block_scheduling(entry, reason="claims_compliance unverified within 7d window")
       notify(devon, entry)
   ```
2. **Backfill: reconcile the 7 idea-stage posts** identified in D13 today against the claims enum. Each gets a `claims_compliance` value (`approved`, `revised`, `rejected`, or stays `not_checked` if not yet reviewed -- in which case the gate fires).
3. **Documentation:** Update D13 calendar tooling spec to reference the new gate.
