## Hypothesis

ZSquared 3P reseller partnership is signed; Kenetik retains Brand Registry but cedes Amazon seller-of-record + Amazon Ads account on transition complete. Amazon channel intelligence post-transition requires three combined inputs:

1. **Brand Analytics ingestion via Brand Registry** — covered by CS-2026-091 rescope (Kenetik-side, retains).
2. **ZSquared weekly reporting feed ingestion** — this CS (3P-side, partner data).
3. **Public competitive scraping** (Helium 10 / Jungle Scout) — separate workstream (TBD).

ZSquared feed + Brand Analytics is a stronger combined view than running 1P FBA gave us, because brand-side data + first-party 3P reporting > seller-side data alone.

## Resolution Path (Diagnose / Remove / Refine / Add)

- **Diagnose:** Once ZSquared is exclusive seller, Kenetik loses direct Amazon Ads + Seller Central reporting. The KGS Amazon view goes dark unless we ingest from somewhere.
- **Remove:** Nothing existing handles this — the original Domain 03 scan pulled from Polar's `amazon-selling-partner` + `amazon-ads` connectors, which assume Kenetik is the seller. Now paused (`shared-config.json` → `paused_domains.03`).
- **Refine:** Brand Analytics pivot (CS-091) covers the brand-side. This CS adds the 3P-side via ZSquared's reporting feed.
- **Add:** New `scripts/zsquared_feed_ingest.py` + new GHA workflow + new output file. Justified because no existing pipeline ingests partner-reported reseller data.

## Distribution Surfaces (the data ZSquared has agreed to provide)

Per the partnership data-sharing terms (negotiated 2026-05-04), ZSquared will deliver the following feeds:

### Weekly automated drops (CSV or JSON to shared Google Drive folder or S3 bucket)

| Feed | Cadence | Required fields |
|---|---|---|
| **Sales by SKU** | Weekly | ASIN, units sold, gross revenue, ZQ wholesale cost, returns, refunds, net revenue, gross margin |
| **Campaign performance** | Weekly | campaign name, ad type (SP/SB/SD), targeting type, spend, impressions, clicks, attributed sales, ACOS, ROAS, TACOS |
| **Search-term performance** | Weekly | top 200 by spend: search term, match type, impressions, clicks, spend, attributed sales, conversion rate, ACOS |
| **Inventory health** | Weekly | by ASIN: on-hand units, days of cover, stockout days in past 7d, sell-through velocity, low-stock alerts |
| **Buy Box win rate** | Weekly | by ASIN: % session share won by ZQ, % lost (and to whom if ZQ tracks it) |

### Monthly reports
| Feed | Cadence | Required fields |
|---|---|---|
| **Promotional results** | Monthly | by promotion: type (S&S, Brand Tailored, Lightning Deal, etc.), discount %, dates, units sold, lift vs baseline, discount cost |

### Per-event reports
| Feed | Trigger | Required fields |
|---|---|---|
| **Vine/Review acceleration outcomes** | Per-program | units distributed, reviews received, average rating, sentiment summary |

## Approach

### Phase 1: Confirm feed format with ZSquared (week of 2026-05-12)

Before writing any ingestion code:

- Confirm delivery method (Google Drive folder vs. S3 bucket vs. SFTP vs. email — preference: shared Drive folder, programmatically accessible)
- Confirm file format (CSV preferred for simplicity; JSON acceptable)
- Confirm column names + data types per feed (so the parser doesn't break on naming drift)
- Confirm cadence + delivery time (e.g., "every Monday by 9am ET" vs. "weekly")
- Confirm contact for feed delivery issues (escalation path)

Owner: Devon (with Josh as ZQ-side coordination contact).

### Phase 2: Build `scripts/zsquared_feed_ingest.py` (~half-day)

Modeled on the existing pattern (`scripts/qb_financial_refresh.py`, `scripts/recharge_subscription_sync.py`, `scripts/shopify_cohort_analysis.py` — same shape as CS-2026-091's amazon_ads_search_terms_pull.py).

- Fetch the latest dropped feed files (auth via Google Drive API or S3 access keys, depending on method)
- Parse each CSV/JSON into structured records
- Validate against expected schema (fail loudly if column names drift)
- Aggregate per the synthesizer's needs (SKU rollups, campaign rollups, etc.)
- Write to `data/amazon/zsquared-reporting-state.json` (single writer, mirrors the `subscription-state.json` / `paid-media-state.json` pattern)

### Phase 3: Add daily GHA workflow

- Schedule: 7:00 AM ET (after Recharge sync at 5 AM and the Amazon Ads pull at 6 AM, so Brand Analytics + ZQ feed land before exec BI runs)
- Manual-trigger only initially; uncomment cron after first successful run validates the integration
- Same commit-and-push pattern as `recharge-subscription-sync.yml`

### Phase 4: Repoint Domain 03 instructions

Update `cgo-daily-pipeline/config/domains/domain-03-instructions.md` to read from the new sources:
- `data/amazon/brand-analytics-state.json` (CS-091 output)
- `data/amazon/zsquared-reporting-state.json` (this CS output)
- (Optional) public competitive scraping output

Move D03 from `paused_domains` → `domains` in `shared-config.json`. Add D03 back to `task-a-scans.md` Batch 1.

## Acceptance Criterion

1. ZSquared delivers first weekly feed in agreed format (Phase 1 confirmation visible in shared folder).
2. `scripts/zsquared_feed_ingest.py` runs successfully against the first delivered feed and produces a valid `data/amazon/zsquared-reporting-state.json`.
3. Daily GHA cron runs successfully for 7 consecutive days without manual intervention.
4. Domain 03 scan resumes (status moves from `paused_domains` back to `domains`) and the daily pipeline produces a valid Domain 03 brief using the new sources.
