## 1. Summary

Extend `/changeset-lifecycle-sweep` Phase 0 (data load) to rebuild `shadow_scorecard.concordance_summary` and `shadow_scorecard.total_classified` idempotently from the authoritative `shadow_scorecard.auto_review_log` on every sweep run. ## 7. Payload — After

Insert a new Phase 0.5 block in `changeset-lifecycle-sweep.md` after "Data Sourcing" and before "Phase 1: Stale Detection". Full text of the block is in the sweep command as committed with this CS. The Read Strategy bullet in Data Sourcing is extended to note that `shadow_scorecard.auto_review_log` is a required read for the rebuild.

Rebuild algorithm (normative, mirrors the command text):

1. Read `tracker.json → shadow_scorecard.auto_review_log[]`.
2. Compute `total_classified` by counting entries per tier (accept `0`/`1`/`2` integer or `"0"`/`"1"`/`"2"`/`"tier_0"` etc. string forms; malformed entries flagged, not counted).
3. Compute `concordance_summary` by counting per `entry.concordance` value (`concordant`, `discordant`, `false_alarm` count as resolved; everything else counts as `pending`). Set `concordance_rate = concordant / total_resolved` rounded to 2 decimals, or `null` if zero resolved.
4. Write back to `shadow_scorecard.total_classified`, `shadow_scorecard.concordance_summary`, and `shadow_scorecard.last_updated = today`.
5. Emit a one-line sweep summary entry: `"Shadow scorecard rebuilt: tier_0=N/tier_1=N/tier_2=N classified, N resolved, R rate."`
6. Runs in every sweep mode (`full`, `stale-only`, `measure-only`).

Tracker.json is also updated in-place in the same commit to reflect a one-time retroactive rebuild, demonstrating the algorithm against current state:

```
total_classified: {tier_0: 1, tier_1: 6, tier_2: 8}  (unchanged — was already correct)
concordance_summary: {total_resolved: 3, concordant: 3, discordant: 0, false_alarm: 0, pending: 12, concordance_rate: 1.0, discordance_count: 0}
last_updated: 2026-04-16
```
