## Root Cause

On March 23, the `sections/hp-product-grid.liquid` template was rewritten for variant suppression (hiding "New Orange Cranberry" and "Limited Edition Cleetus Strawberry Peach" flavors). The rewrite changed the DOM structure and CSS classes, breaking alignment with the JavaScript ATC handlers in `assets/cw-custom-dev.js.liquid`.

Specifically, the rewritten template:
- Removed `.js_parent--box` wrapper class (JS click handler selector: `.js_parent--box .js_home_page_atc`)
- Removed `.js_home_page_atc` button class (JS ATC trigger)
- Removed `select.actual-variantss` hidden variant select (JS reads variant ID from this)
- Removed `.product_dropdown` visible dropdown class (JS change handler selector: `.js_parent--box .product_dropdown`)
- Used non-matching selectors like `.atc-button` and `select[name="variant-choose"]` that had no JS handlers

Result: clicking "Add to Cart" on the homepage product grid did nothing — no cart add, no drawer open. The button was visually present but functionally dead.

## Evidence

- **Pre-bug (Mar 20):** ATC rate 35.1%, CVR 5.4%, 239 orders, ~$21K/day revenue
- **Bug onset (Mar 23):** ATC rate drops to 15.3% — matches the template rewrite commit date
- **Broken period (Mar 27–Apr 2):** ATC rate 8.6%–13.9%, CVR 1.7%–3.4%, ~67–129 orders/day, $5.5K–$9K/day
- **Fix deployed (Apr 3):** ATC rate recovering to 24.5% (partial day, 102 sessions)
- **Estimated revenue loss:** ~$100K–$130K over the 11-day broken period vs pre-bug baseline

## Resolution

**Fix branch:** `fix/hp-product-grid-atc` → merged to `develop` → merged to `main`

### Template fix (`sections/hp-product-grid.liquid`):
- Restored `.js_parent--box` on the product card wrapper
- Restored `.js_imgbox` on the image container
- Added hidden `select.actual-variantss` with variant data attributes matching JS expectations
- Added `.product_dropdown` class on visible option dropdowns with handleized values
- Added `.js_home_page_atc` class on the ATC button alongside the CSS class `.atc-button`
- Preserved ALL existing CSS classes and element types to maintain visual styling
- Maintained variant suppression logic (handleize checks + metafield `suppressed_ids`)

### JavaScript fix (`assets/cw-custom-dev.js.liquid`):
- Line 325: Changed button text from `'add to cart'` to `'Add to Cart'` (proper casing)
- Line 329: Changed button text from `'sold out'` to `'Sold Out'` (proper casing)

### Outcome classification — `fix_shipped_revenue_signal_inconclusive`

The Liquid template patch shipped per the brief's § Root Cause; the fix landed on Apr 3. Daily revenue post-fix is stable and slightly lifted (+10% vs broken), but the brief's modeled $12.5K-25K/week incremental does not appear in topline. Two readings, both honest:

1. **The bug was not as costly as estimated.** $12.5K-25K/week was modeled by extrapolating broken-vs-pre-bug ATC rate deltas to revenue. Other compounding issues (Mobile UX, traffic mix, paid recency) likely made up most of the broken-period revenue gap. CS-046's standalone lift is real but small.
2. **The lift is real but masked by confounds.** Apr 5 had a $15.9K/day spike (1 of 8 days post-fix) — could be the actual fix-driven recovery showing up as a high-traffic anomaly day. Without ATC-rate data, can't isolate.

**Decision:** classify as `fix_shipped_revenue_signal_inconclusive`. Status `published` → `closed`. Margin actual: not measurable from available data (range $0-$25K possible). Outcome honest: bug fix verified shipped, no regression, topline impact ambiguous.
