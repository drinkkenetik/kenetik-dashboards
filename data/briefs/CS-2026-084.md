## Context

The 2026-04-18 Performance Memory evaluation scored the composite at 64.9% Grade D, a regression from the prior reliable baseline. Phase 2 of the KGS RCA Integration plan ran 5 cluster-level RCAs using method v2.1.1 (committed to `feature/pm-drive-to-a`). Two of those clusters — A (confidence inflation: 18/30 strong entries backed by 1 source) and B (entry_type regression: 30/30 null) — collapsed to a shared root: every producer writes directly to `cross-surface-pm.json` with no gate. Same primitive family (P002 Guardrail-as-input × Provisional Co-emit-lifecycle-marker), same API target.

Bundling is mandatory, not optional — shipping A and B as separate gates would fragment the write path and reopen the drift surface that the Phase 2b pattern library flagged (`Spec-without-runtime-enforcement` anti-pattern, 4 instances logged). See Phase 2c bundle at `cgo-logs/rca-runs/2026-04-19-pm-phase2c-changesets.md`.

## Hypothesis

A single gated write API in front of `cross-surface-pm.json` — required-field validation, inline entry_type classifier, deterministic tier-earned computation from `len(sources)`, flag-then-strict policy rollout, and a time-boxed batch-reconciler to clean the existing 30 null entries and 18 inflated-tier entries — lifts the PM composite by +11–12 points (C3-D4 0→3, C2-D4 2→3, C2-D1 +2–3, C2-D2 0→3, C4-D3 +2). This is the foundational ChangeSet in the PM-DRIVE-TO-A-2026-04-19 portfolio: CS-2026-086 (team signal restoration, Phase 2) is a client of this write-gate.

## Scope

1. **Gated write API** (new) — consolidates N producer write points → 1 entrypoint with gate logic:
   a. Validate required fields present (entry_type, sources[], confidence, etc.)
   b. Inline classifier derives entry_type from source-surface + entry shape (rules-based v1)
   c. Compute `earned_tier = max_tier_allowed(len(sources))` per tier table
   d. If `declared_tier > earned_tier`: `policy=flag` auto-downgrades + logs; `policy=strict` rejects
   e. Co-emit derived fields (archival lifecycle marker per Provisional pattern) alongside producer-supplied fields
2. **Producer cutover** — single API swap; no producer internal logic changes required
3. **Policy config** — `flag` (launch default) | `strict` (post-stabilization, 48h clean telemetry gate)
4. **Batch-reconciler worker** — time-boxed run over the existing store: backfill the 30 null `entry_type` entries (classifier) + downgrade the 18 inflated-tier entries (tier-earned)
5. **Low-confidence review queue** — surfaces auto-downgrades + classifier uncertainty cases for human check (prevents silent drift the other direction)
6. **Shadow dry-run** — gate runs read-only for 24–48h before cutover; compares gate decisions to live writes and flags disagreements

## Measurement Plan

- **Primary:** PM composite eval at post-ship +1 week. Target ≥85% Grade A on next scheduled eval; this ChangeSet contributes +11–12 pts of the +22–26 pt portfolio projection.
- **Gate-level:** classifier error rate (target <5%; triggers P003 circuit-breaker fallback to flag-policy if exceeded); reconciler completion (target 100% of 30 null + 18 inflated within 7 days)
- **Secondary:** percent of writes arriving with all required fields pre-populated (producer behavior signal); low-confidence queue volume (calibration signal)
- **Window:** 14 days from first production write through the gate
- **Falsification criteria:** if composite < 82.3% (conservative scenario from Phase 2d prediction doc) at post-ship +1 week, treat as primary miss and escalate to fallback bench A4 (binary confidence taxonomy) + B4 (binary entry_type taxonomy)
