## Context

The 2026-04-18 PM eval flagged C1-D3 (team-signal dimension) as regressed: 30/30 active entries are non-team-source. The Cluster D RCA initially attributed this to a broken or never-real automated producer (hypothesized as a "Slack-listener / retro-capture / 1:1-summarizer" infrastructure stack) and proposed a bifurcated intervention (Phase 1 weekly ceremony + Phase 2 team-ingest service) gated on a post-ship disambiguation audit.

The disambiguation audit (`cgo-logs/audits/2026-04-Wk4-cluster-d-phase1-disambiguation.md`, 2026-04-19) resolved the ambiguity and corrected the producer model:

- **The Slack-listener / retro-capture / 1:1-summarizer producers are fictional.** No such services or commits exist. Git archaeology returned zero hits.
- **The actual producer is the Step 9 → Step 5b path in `cgo-daily-pipeline`.** Step 9 of `synthesis-instructions.md` emits `LEARNING SIGNAL:` blocks; Step 5b of `task-b-synthesis.md` reads those blocks and writes `source_type: team_feedback` entries to `cross-surface-pm.json`. This path is wired, healthy, and has been emitting `LEARNING SIGNALS: 0 new today.` faithfully for the window leading into the 2026-04-18 eval.
- **The regression is in producer coverage, not producer runtime.** Step 9a searches public/private Slack channels with a narrow keyword set; Step 9a.1 reads DM reply-threads tied to prior-session dispatch messages. Neither covers **unsolicited inbound DMs to Devon** — the exact channel Katie Spaller used to deliver L-001 and L-002 on 2026-04-02.

The D5 weekly ceremony is removed from scope — it instantiates the `Spec-without-runtime-enforcement` anti-pattern (logged; see EC-2026-004). The Phase 2 team-ingest service is removed from scope — there were no fragmented producers to consolidate. This ChangeSet ships as a single-fix, single-root-cause intervention.

## Hypothesis

A new Step 9a.2 in `synthesis-instructions.md` that scans Devon's recent unsolicited-inbound Slack DMs for correction-shaped content — emitting LEARNING SIGNAL blocks in the same format as 9a and 9a.1 — restores team-signal producer output by closing the inbound-DM coverage gap. Expected effect: team-signal emissions resume at the historical L-001/L-002 cadence (≥1 new team_feedback entry per 2–3 week window), lifting C1-D3 from dormant (0) to scoring (≥3) in the next eval cycle and contributing +2–3 pts to the portfolio composite (C1 composite 61.1% → ~77.7%).

If empirical team volume is genuinely low (not a coverage gap but a signal-absence), the fix remains correct but yields 0 emissions. Distinguishing these in post-ship measurement is explicit in the falsification criteria below.

## Scope

1. **`synthesis-instructions.md` Step 9a.2 (new)** — between existing 9a (keyword search) and 9a.1 (DM reply-threads), insert:
   > **Step 9a.2: Scan unsolicited inbound DMs to CGO inbox.**
   > Use `slack_search_public_and_private` with author-filter on known team-roster IDs and recipient-filter on Devon's DM channel, time-window = last 72h, excluding threads already surfaced by 9a.1. Apply the same LEARNING SIGNAL extraction logic as 9a: if message contains a CORRECTION, DISAGREEMENT, or substantive FACTUAL OVERRIDE of pipeline output, emit a LEARNING SIGNAL block per 9c. If message is a ROUTINE QUESTION or ACKNOWLEDGMENT, do not emit.

2. **Team-roster config** — create `cgo-daily-pipeline/config/team-roster.json` with stable Slack user-ID list so 9a.2 has an authoritative author filter. Owner maintains. Initial seed: Katie Spaller, Brandon, Frenser, Martyn (expandable).

3. **Keyword broadening (narrow)** — add the minimum set of additional correction-shaped phrases that would have caught the L-001 / L-002 content if scanned against it: `"not quite right", "more nuance", "worth flagging", "fyi", "one thing to note"`. This is a targeted extension only; not a blanket expansion. Tested by replaying against L-001/L-002 source DMs.

4. **No changes to Step 5b.** The write path is correct. The inferred `source_type` logic already tags `team_feedback` on Slack-sourced corrections.

5. **Backfill sweep (one-time, time-boxed)** — run a single retrospective scan over 2026-04-02 → 2026-04-18 applying the new 9a.2 rule to recover any team-source corrections that were missed during the coverage gap. Output: list of candidate entries for CGO review; accepted entries get filed with a `backfill: true` flag and a dated source citation. Time-box: 2 hours.

## Measurement Plan

- **Primary:** PM composite eval at post-ship +1 week. Target: C1-D3 dimension scores ≥3 (from 0 dormant); C1 category composite ≥77%. Contributes +2–3 pts of the portfolio +22–26 pt projection.
- **Secondary:** at least 1 new `team_feedback`-tagged entry written through Step 5b via 9a.2 emission within the first 2 weeks post-ship. Excludes backfill entries (those are separately flagged).
- **Backfill outcome:** report count of backfill candidates surfaced and count accepted. Informs whether the coverage gap was the dominant factor (high count) or whether team signal volume is genuinely low (low count).
- **Window:** 14 days from ship.
- **Falsification criteria:** if the backfill sweep surfaces ≥3 missed corrections in the 16-day lookback but the forward window still produces 0 new team_feedback entries in 14 days, the fix is incomplete — reopen RCA with the narrower hypothesis "coverage extension works for past signals but forward volume is blocked by something else." If backfill surfaces 0 corrections and the forward window also produces 0, team signal is genuinely low-volume and the dimension regression reflects reality; the dimension's scoring criterion in the eval needs recalibration rather than a producer fix.
