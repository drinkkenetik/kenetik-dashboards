## Hypothesis

The content calendar is an append-only publish-LOG with no forward-scheduling step, so cadence targets (TikTok 21/wk, LinkedIn 2/wk) and category tagging are unenforceable by construction. Instituting a forward-scheduling + category-tag pass will restore enforceable owned-organic cadence and lift owned-organic contribution to new_customer_count.

## Resolution Path (Diagnose / Remove / Refine / Add)

- **Diagnose:** The content calendar (content-calendar-data.json, 1,034 entries) is 100% historical — 0 entries dated on/after today. It is a publish-LOG that records what shipped, with no field or process that reserves future slots. Cadence targets and category tags therefore describe the past, not a plan. Three "symptoms" (July-4 owned-organic gap; TikTok 1/21 + LinkedIn 0 cadence collapse; calendar_quality 0.22 + 54% null category) are one root cause. content_mix_targets are additionally frozen at the week of 2026-03-16, so mix-vs-target cannot be reported.
- **Remove:** Remove the false framing that these are separate problems (do NOT add a 4th tracker per Market-Intel CSI-1). Retire the stale content_mix_targets lock.
- **Refine:** Institute a recurring forward-scheduling pass: for the next 14 days (before TRX 7/16), schedule + category-tag owned-organic slots to the platform cadence targets (TikTok 21/wk, LinkedIn 2/wk, IG on-target, FB de-weighted away from QuikTrip retail dupes). Unlock content_mix_targets to the current week so mix-vs-target becomes reportable. This is a process/tooling refinement, not new infrastructure.
- **Add:** Only if refinement proves insufficient — e.g., a lightweight scheduling field/checklist in the calendar data contract. Justify before adding.
