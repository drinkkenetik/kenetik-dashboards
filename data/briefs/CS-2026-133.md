## §10b RESOLUTION PATH ANALYSIS

**Diagnose:** Tracker.json's recent 30 closed CSes have only 27% (8/30) with all five timestamps (`created`, `routed_date`, `approved_date`, `published_date`, `closed_date`) populated AND sane. Specific failures: 63% missing `published_date`; 37% missing `approved_date`; 23% missing `routed_date`; 10% have `routed_date < created` (impossible — backfill artifact). This corrupts the primary signal CS-129 Pass B reads (median process-step duration). Without clean timestamps, automation-opportunity analysis cannot reliably target a step.

The transitions happen in three commands: `/changeset-review` (sets `status=approved`), `/changeset-execute` (sets `status=published`), `/changeset-measurement` (sets `status=closed`), plus `/changeset-lifecycle-sweep` auto-close path. Each *should* write the corresponding timestamp at transition. The data shows they don't always.

**Remove:** Nothing.

**Refine:** Two complementary refinements to existing surfaces. No new infrastructure.

**Add:** Nothing fundamentally new — both refinements are inside existing commands.

## PROPOSED CHANGE — applied in this commit

### Half A — Sweep Phase 4 audit pass (backfill / catch existing gaps)

Adds an audit step inside `kenetik-growth-system/commands/changeset-lifecycle-sweep.md` Phase 4 (Canonical Metadata Writeback). The sweep already iterates non-archived CSes; the audit costs almost nothing.

For each non-archived CS:
- `status=approved` → `approved_date` must be set
- `status=published` → `published_date` must be set
- `status=closed` → `closed_date` must be set
- `status=rolled_back` → `rolled_back_date` must be set

If missing, infer in order: (1) `last_updated`, (2) most-recent commit on the CS file, (3) most-recent sweep_flag.set_date. If any returns a sane date, set the timestamp and flag `timestamp_inferred_from_<source>`. Else flag `timestamp_missing_for_status_<status>` for human attention.

Also flag `routed_date < created` cases as `timestamp_inverted_briefing_negative` for human attention; do NOT auto-fix (could mask real data issues).

### Half B — Forward-looking command hardening

Updated three command files to make timestamp writes explicit at the moment of status transition:

- `changeset-review.md` — APPROVE branch sets `approved_date` + `last_updated`
- `changeset-execute.md` — execute path sets `executed_date` + `published_date` + `last_updated`
- `changeset-measurement.md` — close path sets `closed_date` + `last_updated`

The lifecycle sweep auto-close path (Phase 2 Step 3A) already sets `closed_date`; verified.
