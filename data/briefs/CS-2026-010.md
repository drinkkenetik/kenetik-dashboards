## 1. Summary

Audit Klaviyo profile property definitions and Superfiliate→Klaviyo data flow to determine why Superfiliate-acquired customers cannot be attributed at the Klaviyo profile level, and design a property schema that enables reliable source attribution for flow routing, segmentation, and lifecycle targeting.

## 2. Objective

**Optimization Hierarchy Level:** L4 — Rate of Learning
**Department:** lifecycle-marketing
**Platforms:** [klaviyo]

This investigation closes a systemic data literacy gap identified during CS-2026-001 execution (Learning Note #9). The KGS built segment logic assuming `$source` contained traffic source attribution data (e.g., "Superfiliate"). In reality, `$source` contains Klaviyo form/consent IDs (numeric values like `-154`, `-50`, `-9`, or form names like "Ketone Aware Pop Up - Free 3-Pack"). This gap caused a failed conditional split design that required emergency rearchitecting mid-execution.

Without resolution, every future ChangeSet that attempts Superfiliate-specific routing in Klaviyo will encounter the same failure — wrong assumptions about available data → wrong architecture → wasted execution time.

## 6. Payload — Before (Current State of Understanding)

### What we know:
1. **`$source` property** — Contains Klaviyo form/consent IDs, NOT traffic source attribution
   - Example values observed: `-154`, `-50`, `-9`, `"Ketone Aware Pop Up - Free 3-Pack"`
   - Set automatically by Klaviyo when a profile is created via a form submission
   - Cannot be used for traffic source segmentation

2. **`sf_` prefixed properties** — Written by Superfiliate integration to **creator/partner profiles only**
   - Properties: `sf_shop_name`, `sf_email`, `sf_phone`, `sf_first_name`, `sf_last_name`, `sf_enrolled`, `sf_should_configure_instagram`, `sf_should_configure_paypal`, `sf_should_configure_lumanu`, `sf_unlocked_gifts_count`, `sf_balance`, `sf_raw_balance`, `sf_portal_url`
   - NOT present on customer profiles — cannot be used to identify Superfiliate-acquired customers

3. **Superfiliate metrics in Klaviyo** — 6 metrics exist:
   - `Superfiliate Signed Up` (SzzSmg)
   - `Superfiliate Enrolled` (WarDne)
   - `Superfiliate Campaign Conversion` (TcAUXT)
   - `Superfiliate Campaign Reactivation` (WMsFYR)
   - `Superfiliate Gift Unlocked` (UZ2Nun)
   - `Superfiliate Request Declined` (YzSzvk)
   - **Hypothesis:** `Superfiliate Campaign Conversion` may fire on customer profiles when they convert via a creator link — needs verification

4. **Shopify order tags** — Superfiliate adds tags to associated orders (confirmed in Slack: "this tag is added to orders that ARE superfiliate associated")
   - These tags flow to Klaviyo via the Shopify integration as `Shopify Tags` on profile properties
   - **Potential attribution path** — but tag format and reliability need auditing

5. **Polar Analytics** — `custom_5144` dimension attributes 601 orders to Superfiliate (CS-2026-004 finding)
   - Uses Shopify tags + promo codes for attribution
   - Proves the data exists in Shopify — question is how it flows to Klaviyo

### What we don't know:
- Whether `Superfiliate Campaign Conversion` metric fires on customer profiles (not just creator profiles)
- What event properties are included in Superfiliate metric events (creator ID, campaign ID, referral URL?)
- Whether Shopify Tags containing Superfiliate attribution reliably appear on all Superfiliate-acquired customer profiles in Klaviyo
- Whether a custom Klaviyo property (e.g., `acquisition_source: superfiliate`) could be set via Superfiliate webhooks, Shopify Flow, or Klaviyo API
- Full inventory of Superfiliate→Klaviyo data touchpoints

## 12. Learning Notes

**Completed 2026-04-06.**

For [Superfiliate-acquired customers] on [Klaviyo], [full property audit via Klaviyo API + manual UI verification] revealed [a complete absence of customer-facing Superfiliate data in Klaviyo]. Key insight: **All Superfiliate data in Klaviyo lives on creator profiles — zero data reaches customer profiles, and Shopify order tags do not reliably propagate to Klaviyo Placed Order event properties.**

### Finding 1: All 6 Superfiliate metrics fire on CREATOR profiles only
- Sampled 200 `Superfiliate Campaign Conversion` events → 17 unique profiles, ALL creators (Cleetus, Roman, Doc, Dave Asprey, etc.)
- Zero customer profiles received any Superfiliate metric event
- All events carried empty event properties `{}` — no order ID, no customer reference, no conversion amount
- `sf_communication_type` on creator profiles is always `new_conversion` — this is a creator notification, not customer attribution

### Finding 2: `$source` contains Klaviyo form IDs, NOT traffic source
- Observed values: `-154`, `-50`, `-9`, `-5`, `-6`, `-127`, `"Ketone Aware Pop Up - Free 3-Pack"`, `"UE | Multi-step Desktop 2026"`, etc.
- Segment "Influencer-Acquired - All Creators" (U22Pai) uses `$source contains superfiliate` — this definition is **BROKEN** and returns incorrect results

### Finding 3: `sf_` profile properties exist ONLY on creator profiles (~40 properties)
- Properties like `sf_code`, `sf_revenue`, `sf_referred_customers_count` are written by Superfiliate integration
- Never present on customer profiles — cannot be used for customer attribution

### Finding 4: Shopify order tag `superfiliate conversion approved` does NOT reliably propagate to Klaviyo
- **Shopify side:** Tag is present and reliable (105 orders tagged in a single day)
- **Klaviyo side:** Created test segment "Superfiliate TEST" filtering Placed Order where Tags includes `superfiliate conversion approved` → only 10 profiles matched out of thousands of expected Superfiliate orders
- Manually checked a known Superfiliate order's Placed Order event in Klaviyo UI → Tags section was blank
- **Conclusion:** Shopify order tags are NOT flowing through to Klaviyo's Placed Order event properties. A Klaviyo-only flow approach (trigger on Placed Order + filter by tag) will NOT work.
- **Shopify Tags profile property:** Contains customer-level tags (Active Subscriber, tier levels, Shop, Club) but NOT order-level Superfiliate tags

### Finding 5: Discount code matching is the only working attribution method today
- Existing segments like "UE | Cleetus Audience" (Yqj4WM) successfully use `Discount Codes contains-substring "cleetus"` on Placed Order events
- Limitations: misses code-less conversions, requires manual code list maintenance, event-level only (not profile-level)

### Recommended Fix
**Shopify Flow → Klaviyo API** (CS-2026-049): Trigger on order creation in Shopify where order tag = `superfiliate conversion approved`, extract discount code, write `acquisition_source` and `referring_creator` to Klaviyo customer profile via API. Must use Shopify Flow (not Klaviyo Flow) because the tag data lives in Shopify and does not reach Klaviyo.
