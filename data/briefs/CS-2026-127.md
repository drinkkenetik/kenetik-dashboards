**Department:** operations

**Subtype:** implementation

## Source

- Today's sub-agent sweep silently failed measurement leg — `measured: 0` reported against `measurement_overdue: 6`. CS-016 + CS-017 + CS-046 + CS-006 + CS-018 + CS-040 sat in measurement-overdue limbo until manual intervention.
- Skill file already carries explicit "MUST RUN IN MAIN SESSION" warning. The warning is read by humans authoring briefs; it is not read by the orchestrator that runs the sweep.
- Phase 0.8 MCP probe exists and detects unavailability — it just doesn't act decisively on the detection.

## Resolution Hierarchy applied

### Diagnose (the structural root cause, not the symptom)

The lifecycle sweep is one command that fuses two semantically different operations with different runtime requirements:

| Operation | MCP needed? | Works in sub-agent? | Works in main session? |
|---|---|---|---|
| **Detection** (read tracker.json, identify overdue/stale items) | No | Yes | Yes |
| **Measurement** (Layer 2 pulls from Klaviyo / Polar / Sprout / Superfiliate / Cin7) | Yes | **No** | Yes |

When the cgo-daily-pipeline scheduled task invokes the sweep from a sub-agent context, MCPs aren't inherited. Phase 0.8 detects this and tags individual CSes as `deferred_mcp_unavailable`, but the sweep continues and writes `last_sweep_counts.measured: 0`. The count is technically true and operationally misleading — it reads "0 things were measured" when the real meaning is "0 things were measured because MCPs weren't available." Same number, different story.

**Root cause:** the sweep's reporting layer doesn't distinguish "nothing was measured" from "measurement was deferred because preconditions weren't met." That's the silent-failure mechanism. A warning at the top of a skill file is documentation; it isn't a control surface.

### Remove (eliminate before adding)

Two things to remove:

1. **`last_sweep_counts.measured: 0` semantics when MCPs were unavailable.** The field's name implies "we tried and got zero." When MCPs are missing, we didn't try — that should be a different field with a different name.
2. **The implicit "warning at the top of the skill file" as the protection mechanism.** It works as documentation. It doesn't work as control. The orchestrator violates it; the orchestrator doesn't read it.

Cannot remove:
- The cgo-daily-pipeline scheduled run. Daily lifecycle hygiene (stale detection, draft-overdue scanning, taxonomy parity) is real work that belongs in automation. The sub-agent context is fine for *that*; it just isn't fine for measurement.

### Refine (adjust existing mechanisms)

Phase 0.8 already probes MCPs. Three small refinements close the loop without adding any new commands or new data stores.

**1. Phase 0.8 sets one boolean: `measurement_capable: true | false`.**
This already happens implicitly per `mcp_available`. Make it explicit and authoritative.

**2. When `measurement_capable: false`, write a `pending_measurement_queue` to `tracker.json` and skip Phase 2.**
The queue is a flat list of CS-IDs whose Layer 2 measurement was deferred. tracker.json already carries the data; we're adding one field, not a new store.

```yaml
# tracker.json shape addition
lifecycle_sweep:
  pending_measurement_queue:
    - { cs_id: "CS-2026-016", deferred_at: "2026-04-28T16:35:00Z", reason: "klaviyo_mcp_unavailable" }
    - { cs_id: "CS-2026-017", deferred_at: "2026-04-28T16:35:00Z", reason: "klaviyo_mcp_unavailable" }
    # ...
```

**3. When `measurement_capable: true`, drain the queue at the start of Phase 2.**
Phase A (Detection) appends today's newly-overdue CSes to the queue; Phase 2 measures every CS in the queue (today's + any deferred from prior sub-agent runs); Phase 2 clears the queue on success per CS. Same command, behavior adapts to context.

**4. `last_sweep_counts` shape reflects the new contract.**
Replace `measured: <int>` semantics with the explicit triple:

```yaml
last_sweep_counts:
  measurement_overdue: 6           # what Phase A detected as needing measurement
  measured: 0                      # what Phase 2 actually measured this run
  measurement_deferred: 6          # what got queued because MCPs unavailable
  pending_measurement_queue_size: 6  # total backlog (incl. prior runs)
  auto_closed: 0                   # what got auto-closed after measurement
```

Now `measured: 0 / deferred: 6` makes the failure mode legible at a glance. The morning sweep can no longer claim it measured zero things when it actually skipped six things.

**5. Optional Slack nudge on detection-only runs.**
On any sweep where `measurement_deferred > 0`, post a single line to `#kgs-ops`: *"Detection sweep clean. 6 CSes queued for main-session measurement; run `/changeset-lifecycle-sweep` from any main session to drain."* This is the human-loop signal that actually fires at the right time — at sub-agent invocation, not at brief-author time.

### Add: nothing

No new commands. No new data stores. No new services. The fix is one new field in tracker.json (`pending_measurement_queue`), one shape change to `last_sweep_counts`, one conditional on `measurement_capable` in the sweep flow, and one optional Slack ping. Total touched code surface: the existing `changeset-lifecycle-sweep.md` skill + a config touch on `cgo-daily-pipeline` if we wire the Slack nudge.

## Why this is elegant per the Design Principles

| Principle | How this fix honors it |
|---|---|
| **Honors the actual constraint** | MCPs need main session — the fix doesn't fight that, it routes around it |
| **Same surface, adaptive behavior** | One command works in both contexts; no command-set proliferation |
| **Existing data store carries the queue** | tracker.json already exists; we add one list, no new database |
| **Failure becomes legible** | `measurement_deferred: 6` is the loud, honest version of `measured: 0`; the operator sees the failure mode at a glance |
| **No human ceremony required** | The next main-session sweep drains the queue automatically; no "remember to run X" |
| **Kills the silent failure mode** | The exact symptom Devon hit cannot recur — a sub-agent run physically cannot claim to have measured what it didn't |
| **Removes more than it adds** | Removes the misleading count semantics; removes the warning-as-control pattern; replaces with explicit field + queue |

## What this does NOT do (deliberately out of scope)

- **Doesn't change cgo-daily-pipeline scheduling.** Daily sub-agent runs continue. They just become honest about their own scope.
- **Doesn't add a new "main session detector" beyond MCP probe.** The MCP probe IS the detector. We don't need a separate session-type identifier.
- **Doesn't try to make sub-agents inherit MCPs.** That's a platform property of how Claude's MCP layer works; the fix routes around it instead of fighting it.
- **Doesn't auto-close anything new.** The auto-close logic for measured-and-passing CSes is unchanged.

## Implementation surface (small)

1. `kenetik-growth-system/commands/changeset-lifecycle-sweep.md` — extend Phase 0.8 with the queue-write/queue-drain logic; rewrite `last_sweep_counts` shape in the documented output.
2. `cgo-logs/changesets/tracker.json` schema — add `lifecycle_sweep.pending_measurement_queue: []`.
3. `cgo-daily-pipeline` orchestrator config — add Slack post-sweep nudge when `measurement_deferred > 0` (optional, but recommended).
4. (Optional) Add a one-line warning at the top of the existing skill warning that says: *"This warning is documentation, not control. The control is the queue."* So next reader knows the actual mechanism.

## Measurement plan (for this fix itself)

- **Primary metric:** `last_sweep_counts.measured` matches `last_sweep_counts.measurement_overdue` on main-session runs. On sub-agent runs, `measurement_deferred` ≥ 1 instead of `measured: 0`.
- **Secondary:** zero CSes sit measurement-overdue for >7 days (queue drains within one main session per week minimum cadence).
- **Window:** 14 days post-implementation.
- **Kill gate:** if any CS sits in `pending_measurement_queue` for >14 days without being measured, the queue-drain mechanism failed and we escalate.

## Expected impact

- L1 margin: neutral directly. Indirect: prevents future $K-scale missed-measurement opportunities by surfacing them on day 1 instead of day 18.
- L4 learning: codifies the "honor the constraint, route around it" pattern for future sub-agent ↔ MCP mismatches.
- L5 brand check: pass.

## Notes

- The today incident (six CSes deferred silently) is the proof case. CS-046 sat for 18 days. CS-006 for 15 days. The decay-cost compounds: stale CSes are harder to attribute, easier to misclose, and create downstream "phantom dependency" patterns (per L-053).
- This is the same anti-pattern as CS-096's auto-close mechanism not firing — both cases were "the right policy is documented but the orchestrator doesn't enforce it." Pattern: when a policy is written for a sub-agent to follow, the policy must be wired into the sub-agent's runtime, not into the human-facing skill file.
